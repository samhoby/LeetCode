# 2089. Find Target Indices After Sorting Array

- **Difficulty:** Easy
- **Topics:** [Mid Level](../README.md#mid-level), [Array](../README.md#array), [Binary Search](../README.md#binary-search), [Sorting](../README.md#sorting)
- **Link:** https://leetcode.com/problems/find-target-indices-after-sorting-array/

## Key idea
The array doesn't need to be sorted to know where `target` would end up. After sorting, every number smaller than `target` comes before it, and its copies come right after them. So if k numbers are smaller than `target` and it appears c times, its indices are k to k + c - 1. Counting both in one pass is enough.

Example with `nums = [1,2,5,2,3]` and `target = 2`: only 1 is smaller and 2 appears twice, so the indices are 1 and 2, giving `[1,2]`.

This solution doesn't sort or binary search. Those topics are for the direct approach: sort, then binary search for the first and last `target`, which is O(n log n).

## Pattern
Counting instead of sorting: only how many numbers are smaller, and how many are equal, decide where `target` lands.

## Complexity
O(n) time, O(1) space.
