# 7. Reverse Integer

- **Difficulty:** Medium
- **Topics:** [Math](../README.md#math)
- **Link:** https://leetcode.com/problems/reverse-integer/

## Key idea
Reverse the digits by repeatedly taking the last digit off `x` and appending it to the result (times 10, plus the digit), until no digits are left. The sign stays the same, so a negative `x` gives a negative reverse. The reverse can be too big for 32 bits even when `x` fits, and then the answer is 0.

Example with `x = -123`: the digits come off as 3, 2 and 1, so the reverse is 321, and with the sign it's -321. With `x = 1534236469`, the reverse is 9646324351, which doesn't fit in 32 bits, so the answer is 0.

The problem says to assume 64-bit integers aren't allowed. Both codes build the result in a wider integer and only check it at the end, which LeetCode accepts. The strict way is to check before each step that the result times 10, plus the digit, still fits in 32 bits.

## Pattern
Digit manipulation with mod 10 and divide by 10, like [Palindrome Number](0009.md).

## Complexity
O(log x) time, O(1) space.
