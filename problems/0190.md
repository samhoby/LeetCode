# 190. Reverse Bits

- **Difficulty:** Easy
- **Topics:** [Divide and Conquer](../README.md#divide-and-conquer), [Bit Manipulation](../README.md#bit-manipulation)
- **Link:** https://leetcode.com/problems/reverse-bits/

## Key idea
Build the reversed number one bit at a time. Read the 32 bits of `n` from the lowest to the highest, and each time shift the result one place left and put the bit at its end. After 32 bits, the lowest bit of `n` has moved all the way to the top of the result, and the highest one is at the bottom.

Example with `n = 43261596`, which is `00000010100101000001111010011100`: read backwards, it becomes `00111001011110000010100101000000`, which is 964176192.

Neither code uses divide and conquer. That topic is for another approach: swap the two 16-bit halves, then the two 8-bit halves inside each, then 4, 2 and 1, in 5 steps with masks.

## Pattern
Bit manipulation: read a bit with a shift and a mask, and write it by shifting the result left.

## Complexity
O(1) time, O(1) space.

## Follow-up
If this function is called many times, how would you optimize it?

The code is in [kotlin/0190.kt](kotlin/0190.kt), under `// Follow-up`, and in [python3/0190.py](python3/0190.py), under `# Follow-up`.

Instead of reversing 32 bits on every call, the reverse of every possible byte (256 values) is computed once and saved in `table`. Each call splits `n` into its 4 bytes, looks up the reverse of each one, and puts them back in the opposite order: the lowest byte goes to the top and the highest to the bottom. That's 4 lookups per call instead of 32 steps.

O(1) time per call, O(1) space, since `table` always has 256 values.
