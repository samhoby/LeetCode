# 169. Majority Element

- **Difficulty:** Easy
- **Topics:** [Array](../README.md#array), [Hash Table](../README.md#hash-table), [Divide and Conquer](../README.md#divide-and-conquer), [Sorting](../README.md#sorting), [Counting](../README.md#counting), [Boyer-Moore Majority Vote](../README.md#boyer-moore-majority-vote)
- **Link:** https://leetcode.com/problems/majority-element/

## Key idea
When two different numbers meet, they cancel each other out. The majority element appears more than n/2 times, so all the other numbers combined can't cancel it, and it's the one left at the end.

To do this in one pass, keep a candidate and a count. A number equal to the candidate adds 1, a different one subtracts 1. When the count is 0, the previous candidate has been fully cancelled, so the current number becomes the new candidate and counts itself, starting at 1. Example with `[2, 2, 1, 1, 1, 2, 2]`:

| num | candidate | count |
| --- | --------- | ----- |
| 2   | 2         | 1     |
| 2   | 2         | 2     |
| 1   | 2         | 1     |
| 1   | 2         | 0     |
| 1   | 1         | 1     |
| 2   | 1         | 0     |
| 2   | 2         | 1     |

## Pattern
Boyer-Moore majority vote: different numbers cancel each other in pairs, and only the majority survives. The starting `candidate = nums[0]` doesn't really matter, since `count` starts at 0 and the first number overwrites it.

Alternatives: count with a hash map (O(n) space), or sort and take `nums[n / 2]` (O(n log n) time).

## Complexity
O(n) time, O(1) space.
