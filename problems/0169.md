# 169. Majority Element

- **Difficulty:** Easy
- **Topics:** [Array](../README.md#array), [Hash Table](../README.md#hash-table), [Divide and Conquer](../README.md#divide-and-conquer), [Sorting](../README.md#sorting), [Counting](../README.md#counting), [Boyer-Moore Majority Vote](../README.md#boyer-moore-majority-vote)
- **Link:** https://leetcode.com/problems/majority-element/

## Key idea
Keep a `candidate` and a `count`. A number equal to the `candidate` votes for it (`count++`), a different number votes against it (`count--`). When `count` drops to 0, the `candidate` has been fully cancelled, so the next number becomes the new `candidate`.

The order matters: first check `count == 0` and pick the new `candidate`, then compare. That way the new `candidate` counts its own vote and starts at 1. Example with `[2, 2, 1, 1, 1, 2, 2]`:

| num | candidate | count |
| --- | --------- | ----- |
| 2   | 2         | 1     |
| 2   | 2         | 2     |
| 1   | 2         | 1     |
| 1   | 2         | 0     |
| 1   | 1         | 1     |
| 2   | 1         | 0     |
| 2   | 2         | 1     |

It works because each `count--` cancels one vote of the `candidate` with one different number. The majority element appears more than n/2 times, so it can't be cancelled by everything else combined, and it's the `candidate` left at the end.

## Pattern
Boyer-Moore majority vote: different numbers cancel each other in pairs, and only the majority survives. The starting `candidate = nums[0]` doesn't really matter, since `count` starts at 0 and the first number overwrites it.

Alternatives: count with a hash map (O(n) space), or sort and take `nums[n / 2]` (O(n log n) time).

## Complexity
O(n) time, O(1) space.

## Code
```kotlin
class Solution {
    fun majorityElement(nums: IntArray): Int {
        var candidate = nums[0]
        var count = 0

        for (num in nums) {
            if (count == 0) candidate = num
            if (candidate == num) count++ else count--
        }
        
        return candidate
    }
}
```
